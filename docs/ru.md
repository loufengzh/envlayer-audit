# envlayer-audit: аудит слоёв конфигурации

[English](../README.md) · [简体中文](zh-CN.md) · [Deutsch](de.md)

Инструмент показывает происхождение ключей, строки переопределений и нарушения
политики. Значения не выводятся. Файлы и окружение процесса не изменяются.
Требуется Python 3.10 или новее; запуск из репозитория не требует зависимостей.

## Быстрый старт

Из корня репозитория:

```sh
python -m envlayer_audit examples/base.env examples/production.env --policy examples/policy.json
python -m envlayer_audit examples/base.env examples/production.env --format json
python -m unittest discover -s tests -v
```

Указывайте файлы от низкого приоритета к высокому. `L1` — первый файл, число после
двоеточия — номер строки. `LOG_LEVEL: L1:4 -> L2:1 (1 overrides)` означает одно
переопределение во втором файле. Побеждает последнее корректное присваивание,
включая повторы внутри одного файла. Даже одинаковые значения считаются
переопределением: инструмент их не сравнивает. Автопоиска файлов и обработки
`NODE_ENV` нет.

Необязательная установка: `python -m pip install .`; затем доступна команда
`envlayer-audit`. Для сборки нужен setuptools 77+, который pip может скачать.
Пакет пока не опубликован в PyPI.

## Политика

Сохраните JSON в UTF-8 и передайте путь через `--policy`:

```json
{"required":["REGION"],"allowed":["REGION","LOG_LEVEL"],"protected":["REGION"]}
```

- `required`: ключ обязан присутствовать; пустое значение допустимо.
- `allowed`: полный список разрешённых ключей. Без поля ограничений нет;
  пустой список запрещает все ключи.
- `protected`: не более одного присваивания во всех слоях, включая повтор в том
  же файле. Для обязательного наличия добавьте ключ также в `required`.

Имена точные, регистрозависимые, без шаблонов. Неизвестные поля, повторяющиеся
элементы списков или поля JSON, некорректные имена и обязательные ключи вне
`allowed` отклоняются. При ошибке разбора `complete` становится `false`, все
проверки политики пропускаются и команда завершается неуспешно. Частичный отчёт
не является проверенной итоговой конфигурацией.

## Синтаксис и ограничения

UTF-8 без BOM, LF/CRLF, пустые строки, комментарии `#`, необязательный `export`,
присваивания `KEY=value`; имя соответствует `[A-Za-z_][A-Za-z0-9_]*`.
Значение может быть пустым, без кавычек, в одинарных или двойных кавычках,
но только на одной строке. В двойных кавычках обратная косая черта экранирует
следующий символ для поиска закрывающей кавычки; в одинарных экранирования нет.
После закрывающей кавычки разрешены пробелы или комментарий, отделённый пробелом.
Значения без кавычек не могут содержать кавычки или завершаться обратной косой
чертой. Многострочные значения, продолжения строк и отдельные имена без `=`
не поддерживаются. Подстановки и команды не выполняются. Это ограниченный
диалект аудита, а не полный dotenv или shell. Точная спецификация и API —
в английском README.

Коды завершения: `0` — успех; `1` — нарушение синтаксиса или политики;
`2` — ошибка чтения, UTF-8, политики или аргументов. Ошибки чтения и загрузки
политики выводятся общим сообщением в stderr даже в режиме JSON.

Отчёт содержит имена ключей и номера строк, но не пути, значения или их хеши.
Не помещайте секреты в имена ключей. Текст остаётся в памяти процесса;
файлы читаются целиком. Отчёт не заменяет проверку реального загрузчика приложения.

[безопасность](../SECURITY.md) и [лицензию MIT](../LICENSE).
